# ws 연동과 검수

## 이동 순서

1. Model.navigate가 최신 로그·i3 트리로 세션의 현재 쌍과 con_id를 확인한다.
2. deck/i3.py가 subprocess 인자 배열로 ~/.local/bin/ws <0..9>를 동기 실행한다.
   GUI의 PATH 차이에 영향받지 않도록 Path.home()으로 실제 절대 경로를 만든다.
3. 성공 후 에이전트 행은 [con_id=...] focus, 빈 행은 선택한 워크스페이스의 전체 이름으로 포커스한다.
4. 실제 양쪽 워크스페이스 번호를 다시 조회해 쌍이 맞게 표시됐는지 확인한다.

Enter·마우스·알림 클릭 모두 같은 경로다. 선택만 바꾸는 j/k·g/G·n/N과 서버 갱신은
ws를 호출하지 않는다. 같은 쌍의 다른 에이전트로 이동해도 ws를 한 번 호출하며,
ws 자체의 같은 쌍 재선택 정책에 따라 previous가 보존된다.

ws는 쌍을 떠날 때 실제 포커스 쪽을 관측해 기록하고, 창은 i3의 마지막 포커스를 이용한다.
따라서 ws 전환 뒤 앱이 선택한 정확한 창으로 포커스해도 다음 Mod+Tab에서 그 위치가 반영된다.
앱이 ws 상태 파일을 직접 편집하거나 대상 포커스를 기록하려고 ws를 두 번 호출하지 않는다.

## 오류와 범위

- ws 누락·종료 코드 실패·10초 시간 초과는 오류로 전달하고 이후 직접 포커스를 실행하지 않는다.
- ws 성공 후 최종 i3 포커스 실패나 쌍 검증 실패도 오류로 전달한다. 이미 기록된 이력을
  임의로 되돌리거나 ws를 다시 호출하지 않는다.
- 쌍 밖의 창은 기존처럼 해당 창만 포커스한다. 임의의 ws 목적지를 만들지 않는다.
- i3·ws·dunst 설정 파일은 수정하지 않는다. 기존 ~/.local/bin/ws 설치가 필요하다.
- 알림 클릭은 서버 재시작 이후에 생성된 새 알림으로 검수한다.

## 자동 검사

```bash
python3 -m unittest discover -s tests -v
python3 -B tests/ws_navigation_check.py
# Xvfb가 PATH에 없고 별도로 준비돼 있다면:
python3 -B tests/ws_navigation_check.py --xvfb /path/to/Xvfb
```

단위·서버·TUI 테스트 65개 통과. ws 인자 1..9/0, 한 번 호출, 최종 IPC보다 먼저
호출되는 순서, 전체 이름의 좌우 빈 행, ws 누락·실패·시간 초과, i3 실패와 잘못된 쌍 검증을 포함한다.
기존 TUI/서버 테스트로 Enter·클릭·알림의 공통 이동과 선택만으로 이동하지 않는 것도 확인한다.

통합 검사는 ~/.config/i3/tests/workspace_regression.py의 Desktop 도우미를 읽어
임시 Xvfb·i3·runtime을 만든다. --harness PATH로 별도 도우미 경로를 지정할 수 있다.
운영 DISPLAY·i3 소켓·X 인증은 사용하지 않으며 운영 ws 상태 파일을 건드리지 않는다.
실제 ws와 Model.navigate로 다음 40개 시나리오를 통과했다.

- 10개 쌍 × 좌우 에이전트: 출발 쪽 기록, Mod+Tab 왕복의 쌍·정확한 창 복귀,
  같은 쌍 안의 다른 에이전트 선택 시 previous 유지와 최종 포커스 반영.
- 10개 쌍 × 좌우 빈 행: 선택한 쪽 포커스와 Mod+Tab 왕복 복원.

이번 환경에서는 기존에 준비된 /tmp/i3-native-pair-test/root/usr/bin/Xvfb를 사용했다.
실제 터미널·마우스의 이벤트 타이밍과 데스크톱 알림 클릭은 아래 사용자 검수로 확인한다.

## 사용자 검수 목록

서로 다른 쌍 A와 B를 골라 확인한다. 출발할 때 실제 포커스는 deck TUI 창이며,
Mod+Tab으로 돌아올 때 그 쪽·창이 복원되는 것이 기대 동작이다.

- [ ] A의 deck에서 B 에이전트 행을 Enter: 양쪽 모니터가 B로 바뀌고 정확한 에이전트 창에 포커스.
- [ ] Mod+Tab: A의 원래 쪽·창 복원. 다시 Mod+Tab: B의 선택했던 에이전트 창 복원.
- [ ] 마우스 단일 클릭으로도 같은 이동과 Mod+Tab 왕복이 동작.
- [ ] B의 왼쪽·오른쪽 에이전트를 각각 선택해도 최종 포커스와 왕복 복원이 정확함.
- [ ] 같은 쌍의 다른 에이전트 선택 후 Mod+Tab: previous가 그 쌍으로 덮이지 않고 이전 다른 쌍으로 돌아감.
- [ ] [0]의 F0/0 에이전트와 빈 행도 정상 동작. 실제 i3 이름은 F10 그대로 유지.
- [ ] 왼쪽·오른쪽 etc 빈 행을 Enter/클릭: 양쪽 쌍 전환 후 선택한 쪽 포커스. Mod+Tab 왕복도 해당 쪽 복원.
- [ ] j/k·g/G·n/N으로 커서만 이동: 실제 쌍·창이 바뀌지 않고 Mod+Tab의 이전 위치도 바뀌지 않음.
- [ ] 새 완료 알림을 클릭: 발생한 에이전트의 쌍·창으로 이동. Mod+Tab으로 출발 위치에 복귀.
- [ ] 에이전트 터미널을 다른 쌍으로 옮긴 뒤 deck/새 알림으로 이동: 현재 위치로 이동하며 왕복도 정상.

변경 적용은 서버 재시작이 필요하다. TUI 코드는 바꾸지 않았으므로 기존 TUI는 재접속해 쓸 수 있다.
