# 다음 변경 계획

## 범위와 현재 단계

요구사항·설계 문서만 작성했다. 아래 변경은 아직 구현하지 않았다.
현재 실행 코드는 여전히 쌍당 대표 에이전트 한 행을 표시한다.
Python 표준 라이브러리, 공유 서버, 작은 아토믹 커밋 원칙을 유지한다.
i3와 dunst 설정은 이 계획 작성 과정에서 수정하지 않는다.

## 확인된 누락 사례

- 사용자 보고: F10/0 쌍에 실행 중인 에이전트 세션이 총 3개 있다.
- 그중 F10의 `i3 설정` 세션이 deck에 표시되지 않는다.
- 과거 세션을 다시 켰고 작업 디렉토리가 `~`가 아니다.
- 재개 또는 작업 디렉토리가 원인인지는 아직 확인하지 않았다.
- 현재 알림 수집은 대표 행만이 아니라 수집된 모든 세션을 대상으로 한다.
  따라서 다중 행 표시와 별도로 세션 발견·제목 조회·창 연결·완료 감지를 조사한다.
- 첫 검증 기준: 위 3개를 모두 발견하고 실제 워크스페이스에 표시하며,
  각 세션의 새 완료마다 한 번씩 알림을 보낸다.

## 목록 구조

```text
[0] F0  ● 작업 중  에이전트 A
        ✓ 완료    에이전트 B
     0  · 비어 있음
[1] F1  ✓ 완료    에이전트 C
     1  ● 작업 중  에이전트 D
```

- 쌍은 `[0]`, `[1]`, …, `[9]` 순서로 표시한다.
- `[0]`은 실제 F10/0 쌍이다. F10은 화면에서만 F0로 표시한다.
  실제 i3 워크스페이스 `20:F10`과 `10:0` 및 설정은 유지한다.
- 각 쌍 아래 왼쪽 워크스페이스, 오른쪽 워크스페이스 순으로 모든 에이전트를 표시한다.
- 같은 워크스페이스 안의 에이전트는 발견 순서를 유지한다.
- 쌍·워크스페이스 표시는 첫 행에만 쓰고 이어지는 에이전트 행은 들여쓴다.
- 에이전트 없는 워크스페이스는 회색 빈 행으로 남기고 이동할 수 있게 한다.
- 상단 `i3.ai-deck 현재 …` 행은 없앤다. 키 안내·오류 표시 공간은 유지한다.
- 대표 에이전트에 따라 한 행의 제목을 바꾸던 기능은 제거한다.
  각 에이전트 제목은 별도 행에 계속 표시하며 Codex rename 변경은 반영한다.
- 위치를 연결하지 못한 세션은 별도 미확인 영역에 둔다. 빈 자리로 오인하지 않게 한다.
- 종료 기록은 기존처럼 뒤쪽에 두고 서버를 재시작하면 실행 중인 세션만 재발견한다.

## 현재 포커스와 선택

- 실제 현재 쌍의 `[번호]`와 실제 현재 워크스페이스 표시를 청록색으로 강조한다.
- 실제 포커스된 에이전트는 별도 작은 표시로 구분한다.
- 키보드로 선택한 행은 중립색 반전, 완료 상태는 녹색으로 표시한다.
- TUI가 포커스되면 마지막 에이전트 방문 기록과 실제 포커스를 혼동하지 않게 한다.
- 포커스 변경만으로 에이전트 행 순서나 제목을 다른 세션으로 바꾸지 않는다.

## 이동과 조작

- j/k: 에이전트·빈 행 선택. g/G: 목록 처음/끝 선택.
- Enter·단일 클릭: 대상의 최신 위치를 조회하고 양쪽 워크스페이스를 전환한 뒤
  그 에이전트가 있는 터미널 창에 포커스한다.
- 빈 행: 해당 쌍을 열고 선택한 쪽 워크스페이스에 포커스하는 방안을 제안한다.
- n: 모든 워크스페이스의 질문·미확인 완료를 에이전트 단위로 순환한다.
- 선택은 행 번호가 아닌 세션 ID로 유지한다. 창이 이동하면 소속 그룹을 갱신한다.
- Ptyxis 내부 탭 전환은 범위 밖이다. 창 단위로만 이동·확인 처리한다.

## 완료 알림

- 녹색 스타일은 유지하고 본문은 `3: 제목…`, `0: 제목…` 형태의 짧은 한 줄로 한다.
- 쌍 표시 번호 0..9와 내부 슬롯 1..10은 분리한다. 내부 슬롯 10은 화면·알림에서 0이다.
- 제목 표시폭 제한, 말줄임표, 마크업 이스케이프를 유지한다.
- 알림은 각 세션·완료 이벤트를 기준으로 하며, 대표 행·현재 포커스·TUI 개수에
  의존하지 않는다. 처음 발견한 과거 완료를 재알림하지 않는 정책은 유지한다.
- 위치 불명일 때 번호를 추측하지 않는다. 정확한 문구는 구현 시 정한다.

## 알림 액션 연결 제안

1. 기존 notify-send 인자에 `--action=default=이동`을 추가한다.
2. 액션을 기다리는 알림 프로세스와 원본 세션 ID를 서버에서 연결한다.
3. stdout으로 `default`가 도착하면 원본 세션 ID의 이동 요청을 실행한다.
4. 클릭 시점의 i3 트리를 조회해 현재 워크스페이스 쌍과 창을 찾는다.
5. 기존의 양쪽 워크스페이스 전환·대상 창 포커스 기능을 그대로 호출한다.

- notify-send의 action 옵션은 사용자의 선택을 기다리므로 현재의 3초 동기 실행을
  그대로 사용할 수 없다. 별도 비동기 프로세스로 감시하고 서버 상태 갱신을 막지 않는다.
- 알림을 닫기만 했거나 만료된 경우에는 이동하지 않는다.
- 제목을 셸 명령으로 해석하지 않는다. 앱이 세션 ID를 가지고 자체 이동 기능을 호출한다.
- 알림 후 창이 이동하거나 제목이 바뀌어도 원본 세션을 따라간다.
- 원본 세션 종료·창 연결 실패 시 엉뚱한 창으로 이동하거나 세션을 재실행하지 않는다.
- 같은 세션의 새 완료 알림 교체 여부, 대기 중인 알림 프로세스 정리 정책은 구현 시 정한다.

### dunst의 클릭 버튼

- 왼쪽 클릭으로 액션을 실행하기로 정리했다. 오른쪽 클릭 언급은 사용자가 오타로 정정했다.
- 도구·설정·역할 분담 안내는 `bash scripts/dunst-action-help.sh`로 출력한다.
  이 스크립트는 설정을 자동 수정하거나 알림을 보내지 않는다.
- 설치된 notify-send 0.8.8은 action 이름을 stdout으로 반환하는 옵션을 지원한다.
- dunst 기본 설정은 왼쪽 클릭이 닫기, 가운데 클릭이 action 실행이다.
- 따라서 설정 변경 없이 가운데 클릭으로 이동을 지원할 수 있다.
- 왼쪽 클릭으로 이동하려면 dunst의 `[global]`에
  `mouse_left_click = do_action, close_current`가 필요하다.
- 이는 다른 앱의 알림 클릭에도 영향을 줄 수 있다. 실제 변경 범위와 방법은
  추가 논의하며, 현재 문서 작성은 설정 변경의 승인이 아니다.
- 알림 전송 인자만으로 dunst의 왼쪽 클릭 매핑을 강제하지 않는다.

참고: [dunst FAQ](https://dunst-project.org/documentation/faq/),
[알림 액션 명세](https://specifications.freedesktop.org/notification/1.3/basic-design.html).

## 구현 순서와 검수

1. 누락된 재개 세션의 발견·제목·창 연결을 조사하고 3개 세션 재현 사례를 회귀 검증한다.
2. 쌍 → 실제 워크스페이스 → 모든 에이전트 구조와 현재 포커스 표시를 구현한다.
3. 행별 Enter·클릭·n 이동과 창 이동 추적을 검증한다.
4. 짧은 알림 문구와 세션별 완료 알림을 검증한다.
5. 비동기 action 수신·클릭 시점의 쌍/창 이동·대기 프로세스 정리를 구현한다.

쌍 항목 사용자 지정 이름 기능과 일반 승인 대기 감지는 후속 논의로 유지한다.
