# 다음 변경 계획

## 범위와 현재 단계

첫 검수 단위인 누락 세션 수집 수정은 사용자가 검수 완료했다.
두 번째 단위의 별도 에이전트 행·현재 포커스 표시는 사용자 검수 통과했다.
그 후속 UI 피드백(정렬·문구·n 선택·종료 행 숨김)도 사용자가 검수 완료했다.
N의 이전 확인 대상 선택과 서버 재접속을 구현했고 사용자가 클라이언트 유지 동작을 확인했다.
서버 전용 시작 옵션과 코드 역할 분리를 추가하고 검수를 기다린다.
짧은 알림·알림 액션은 아직 구현하지 않았다.
Python 표준 라이브러리, 공유 서버, 작은 아토믹 커밋 원칙을 유지한다.
i3와 dunst 설정은 이 계획 작성 과정에서 수정하지 않는다.

## 확인된 누락 사례

- 사용자 보고: F10/0 쌍에 실행 중인 에이전트 세션이 총 3개 있다.
- 그중 F10의 `i3 설정` 세션이 deck에 표시되지 않는다.
- 과거 세션을 다시 켰고 작업 디렉토리가 `~`가 아니다.
- 재개 또는 작업 디렉토리가 원인인지는 아직 확인하지 않았다.
- 현재 알림 수집은 대표 행만이 아니라 수집된 모든 세션을 대상으로 한다.
  따라서 다중 행 표시와 별도로 세션 발견·제목 조회·창 연결·완료 감지를 조사한다.
- 첫 검증 기준: 위 3개를 모두 발견하고 실제 워크스페이스에 표시하며,
  각 세션의 새 완료마다 한 번씩 알림을 보낸다.

### 1차 구현 결과: 사용자 검수 통과

- 원인: `i3 설정`의 열린 로그는 사용자 스레드이지만 `source=vscode`여서
  기존 `source=cli` 전용 필터에서 제외됐다. 비홈 작업 디렉토리는 원인이 아니었다.
- 사용자 스레드는 원래 출처에 관계없이 수집하며 guardian 등 보조 스레드는 제외한다.
- 한 백엔드 프로세스에서 열린 사용자 로그를 하나만 고르던 제한도 제거했다.
- 실제 세션 연결 확인: F10의 `i3 설정`, F10의 `send-notify 알림 창 제거하기`,
  0의 `i3.ai-deck`을 모두 같은 쌍의 서로 다른 세션으로 확인했다.
- 재개 출처·비홈 작업 디렉토리·공유 백엔드·세 세션의 독립 완료 알림을 회귀 검증했다.
- 1차 검수는 대표 행 방식에서 진행했다. F10/0의 `(+2)`, `i3 설정` 포커스 후
  대표 제목 반영, 해당 세션의 새 완료 알림을 확인하는 방식이었다.
- 사용자 확인: `(+2)` 표시, 대표 제목 변경, `i3 설정` 새 완료 알림 모두 통과했다.
- 출처 확인: 원본(0.167.0)과 재개 로그(0.169.0) 모두 `source=vscode`,
  `originator=codex-tui`다. Codex의 공유 app-server 경로는 `SessionSource::VSCode`를
  사용하므로 터미널에서도 이 값이 기록된다. 실제 VSCode 사용 여부를 뜻하지 않는다.
  [0.169.0 소스](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/cli/src/main.rs#L1278).

### 2차 구현 결과: 기본 표시 검수 통과, 후속 피드백 검수 대기

- 쌍/워크스페이스별 모든 세션 행, `[0]` 우선 정렬, F0 표시를 구현했다.
- 대표 제목·추가 개수·상단 제목을 제거하고 각 제목과 상태를 독립적으로 표시한다.
- 현재 쌍·워크스페이스의 청록색 표시와 실제 에이전트 포커스 `>`를 분리했다.
- Enter·클릭은 세션 ID로 이동하며 빈 행은 선택한 쪽 워크스페이스로 이동한다.
  n은 후속 피드백에 따라 확인 대상 행 선택으로 변경했다.
- 단계 2와 새 행 구조에 필수적인 단계 3의 이동 연결을 한 검수 단위로 제공한다.
- 이 단위에서는 알림 문구나 알림 액션은 변경하지 않았다.
- 테스트 33개와 실제 세 세션의 독립 행을 확인했다. PTY에서 g/G·Enter·단일 클릭,
  실제 i3에서 빈 왼쪽 행·F0와 0의 개별 에이전트 이동을 검증하고 원래 화면을 복원했다.
- 사용자 확인: 별도 행 에이전트 표시와 청록색 현재 위치·실제 포커스 표시는 좋다.

### 후속 UI 피드백: 사용자 검수 통과

- F0의 0과 오른쪽 0, F1의 1과 오른쪽 1이 같은 숫자 열에 놓이도록 오른쪽 정렬한다.
- `빈 쌍`은 `etc`, `비어 있음`은 `에이전트 없음`으로 바꾼다.
- n은 다음 질문·미확인 완료 행에 커서만 옮긴다. Enter를 눌러야 쌍·창 이동과
  확인 처리가 일어난다. 빈 행에서 n을 눌러도 현재 목록 위치를 기준으로 순환한다.
- 사용자 보고 `codex ctrl+l 복구 가능 여부 안내`는 실제 서버에서도 exited,
  alive=False였다. 이전의 종료 기록 유지 정책 때문에 목록 뒤에 남아 있었으므로
  새 요청에 따라 종료 기록을 목록에서 숨긴다.
- 사용자 확인: 모두 정상 작동한다. 추가로 N을 이전 확인 대상 선택 키로 요청했다.

### 서버 재접속과 N: 구현 완료, 검수 대기

- n은 다음, N은 이전 질문·미확인 완료를 순환 선택한다. 둘 다 Enter 전에는
  실제 i3 포커스를 바꾸지 않는다.

- 현재도 `ai_deck.py --server`는 별도 프로세스이며 여러 TUI가 Unix 소켓으로 연결한다.
  실행 파일을 둘로 나눌 필요는 없다. 연결 수명 관리와 재접속 상태 처리가 필요하다.
- 서버 종료·재시작 중에도 TUI를 종료하지 않고 마지막 목록과 연결 대기 표시를 유지한다.
  대기 중 데이터가 실시간 상태처럼 보이지 않도록 현재 포커스 표시는 해제한다.
- 클라이언트가 서버를 강제로 재시작하지 않고 주기적으로 재접속을 시도한다.
  첫 실행 시의 기존 서버 자동 시작 정책은 유지한다.
- 대기 중에도 j/k·g/G·q가 응답해야 하므로 소켓 대기/재시도는 입력 루프를 막지 않는다.
  예외를 잡고 긴 sleep이나 블로킹 재접속 루프에 들어가는 방식은 사용하지 않는다.
- 끊긴 동안의 이동 요청은 쌓아두지 않는다. 재접속 뒤 뜻밖의 창 이동을 방지한다.
- 재접속되면 서버의 새 스냅샷으로 갱신하고, 아직 존재하는 선택 세션 ID는 유지한다.
- 저수준 Client는 유지하고 `deck/connection.py`에 TUI용
  재접속 래퍼를 추가했다. 소켓 대기는 최대 0.2초, 실패 후 단발 재시도는 1초 간격이다.
  긴 sleep이나 무한 접속 루프로 TUI 입력을 멈추지 않는다.
- `deck/tui.py`가 마지막 목록을 회색으로 표시하고 현재 포커스 강조를 해제한다.
  `ai_deck.py`는 TUI에만 래퍼를 사용하며 별도 서버/클라이언트 실행 파일은 만들지 않는다.
- --list/--stop-server 같은 일회성 명령의 종료 방식은 유지한다.
- 실제 PTY와 임시 서버로 정상 종료·강제 종료·재시작을 검증했다. 대기 중 입력,
  재접속 후 변경된 행 순서에서 선택 ID 유지, 이동 요청 재전송 방지, 대기 중 q 종료를 확인했다.
- 사용자 확인: 서버가 종료되어도 클라이언트가 죽지 않는 것은 확인했다.
- 추가 사용자 확인: 서버가 꺼진 상태의 Enter·창 이동에 문제가 없고,
  대기 중인 TUI가 서버 재시작 후 다시 연결된다. 재접속의 핵심 동작 검수 통과.

### 서버 전용 시작과 역할 분리: 구현 완료, 검수 대기

- `--start-server`는 TUI 없이 백그라운드 서버만 시작하고 명령을 종료한다.
  이미 서버가 실행 중이면 중복 생성 없이 사용한다. 응답 가능한지 확인한 뒤 성공을 출력한다.
- 인자 없는 실행은 계속 서버 자동 시작과 TUI 실행을 함께 제공한다.
- `--server`는 기존의 포그라운드 서버 실행 옵션으로 유지한다.
- `deck/server.py`에 있던 저수준 Client·접속·자동 시작 함수를 `deck/client.py`로 옮겼다.
  `deck/protocol.py`는 공통 메시지 크기 상수, `connection.py`는 재접속만 담당한다.
- '대기 중 Enter를 재실행하지 않는다'는 서버가 없을 때 누른 이동 요청 때문에
  서버 재시작 직후 갑자기 창이 이동하지 않게 한다는 뜻이다. 요청을 모아두지 않는다.
- 실제 임시 소켓에서 --start-server를 두 번 실행해 TUI를 열지 않고 하나의 서버를
  재사용하는 것과 정상 종료를 확인했다.
- 중복 검수 방법: --start-server 전후에 `pgrep -af '[a]i_deck.py --server'`로 확인한다.
  기본 서버 한 줄과 동일 PID가 유지되는지 본다. 별도 테스트 소켓의 서버는 구분한다.
- 이번 확인 시 실제 사용자의 기본 소켓을 사용하는 서버 프로세스는 하나였다.

### 원형 확인 표시: 새 계획, 미구현

- 현재 `!`는 미확인 완료 표시다.
- herdr처럼 미확인 완료는 꽉 찬 원 `●`, 확인한 완료는 빈 원 `○`로 표시한다.
- 작업 중·질문 등 기존 상태 글자와 색상, 현재 포커스와 키보드 선택은 별도로 구분한다.
- 이번 변경은 계획 등록만 한다. 실제 아이콘 변경은 별도 검수 단위로 진행한다.

## 목록 구조

```text
[0] F0  ● 작업 중  에이전트 A
        ✓ 완료    에이전트 B
     0  · 비어 있음
[1] F1  ✓ 완료    에이전트 C
     1  ● 작업 중  에이전트 D
```

- 쌍은 `[0]`, `[1]`, …, `[9]` 순서로 표시한다.
- `[0]`은 실제 F10/0 쌍이다. F10은 화면에서만 F0로 표시한다.
  실제 i3 워크스페이스 `20:F10`과 `10:0` 및 설정은 유지한다.
- 각 쌍 아래 왼쪽 워크스페이스, 오른쪽 워크스페이스 순으로 모든 에이전트를 표시한다.
- 같은 워크스페이스 안의 에이전트는 발견 순서를 유지한다.
- 쌍·워크스페이스 표시는 첫 행에만 쓰고 이어지는 에이전트 행은 들여쓴다.
- 에이전트 없는 워크스페이스는 회색 빈 행으로 남기고 이동할 수 있게 한다.
- 상단 `i3.ai-deck 현재 …` 행은 없앤다. 키 안내·오류 표시 공간은 유지한다.
- 대표 에이전트에 따라 한 행의 제목을 바꾸던 기능은 제거한다.
  각 에이전트 제목은 별도 행에 계속 표시하며 Codex rename 변경은 반영한다.
- 위치를 연결하지 못한 세션은 별도 미확인 영역에 둔다. 빈 자리로 오인하지 않게 한다.
- 종료된 세션은 목록에서 숨기고 서버를 재시작하면 실행 중인 세션만 재발견한다.

## 현재 포커스와 선택

- 실제 현재 쌍의 `[번호]`와 실제 현재 워크스페이스 표시를 청록색으로 강조한다.
- 실제 포커스된 에이전트는 별도 작은 표시로 구분한다.
- 키보드로 선택한 행은 중립색 반전, 완료 상태는 녹색으로 표시한다.
- TUI가 포커스되면 마지막 에이전트 방문 기록과 실제 포커스를 혼동하지 않게 한다.
- 포커스 변경만으로 에이전트 행 순서나 제목을 다른 세션으로 바꾸지 않는다.

## 이동과 조작

- j/k: 에이전트·빈 행 선택. g/G: 목록 처음/끝 선택.
- Enter·단일 클릭: 대상의 최신 위치를 조회하고 양쪽 워크스페이스를 전환한 뒤
  그 에이전트가 있는 터미널 창에 포커스한다.
- 빈 행: 해당 쌍을 열고 선택한 쪽 워크스페이스에 포커스하는 방안을 제안한다.
- n/N: 모든 워크스페이스의 질문·미확인 완료 행을 에이전트 단위로 다음/이전 순환 선택한다.
  실제 이동은 Enter로 실행한다.
- 선택은 행 번호가 아닌 세션 ID로 유지한다. 창이 이동하면 소속 그룹을 갱신한다.
- Ptyxis 내부 탭 전환은 범위 밖이다. 창 단위로만 이동·확인 처리한다.

## 완료 알림

- 녹색 스타일은 유지하고 본문은 `3: 제목…`, `0: 제목…` 형태의 짧은 한 줄로 한다.
- 후속 사용자 요청: 현재 알림이 너무 크므로 글자 크기를 줄이고 얇은 한 줄로 표시한다.
  `N: 제목…`의 N은 쌍 번호 0..9다. `xx-large`와 큰 글씨용 굵은 마크업을 제거한다.
- 별도 `Codex` 제목 줄 없이 짧은 문자열을 알림 summary에 넣고 body는 비우는
  방식을 우선 검토한다. 앱 식별자 `-a Codex`는 유지한다. 실제 dunst에서 한 줄 높이를 검수한다.
- 이 요구는 나중의 계획이며 현재 알림 코드는 변경하지 않았다. 추가 dunst 설정이
  필요해지면 당시 필요한 변경을 설명하고 허가를 받는다.
- 쌍 표시 번호 0..9와 내부 슬롯 1..10은 분리한다. 내부 슬롯 10은 화면·알림에서 0이다.
- 제목 표시폭 제한, 말줄임표, 마크업 이스케이프를 유지한다.
- 알림은 각 세션·완료 이벤트를 기준으로 하며, 대표 행·현재 포커스·TUI 개수에
  의존하지 않는다. 처음 발견한 과거 완료를 재알림하지 않는 정책은 유지한다.
- 위치 불명일 때 번호를 추측하지 않는다. 정확한 문구는 구현 시 정한다.

## 알림 액션 연결 제안

1. 기존 notify-send 인자에 `--action=default=이동`을 추가한다.
2. 액션을 기다리는 알림 프로세스와 원본 세션 ID를 서버에서 연결한다.
3. stdout으로 `default`가 도착하면 원본 세션 ID의 이동 요청을 실행한다.
4. 클릭 시점의 i3 트리를 조회해 현재 워크스페이스 쌍과 창을 찾는다.
5. 기존의 양쪽 워크스페이스 전환·대상 창 포커스 기능을 그대로 호출한다.

- notify-send의 action 옵션은 사용자의 선택을 기다리므로 현재의 3초 동기 실행을
  그대로 사용할 수 없다. 별도 비동기 프로세스로 감시하고 서버 상태 갱신을 막지 않는다.
- 알림을 닫기만 했거나 만료된 경우에는 이동하지 않는다.
- 제목을 셸 명령으로 해석하지 않는다. 앱이 세션 ID를 가지고 자체 이동 기능을 호출한다.
- 알림 후 창이 이동하거나 제목이 바뀌어도 원본 세션을 따라간다.
- 원본 세션 종료·창 연결 실패 시 엉뚱한 창으로 이동하거나 세션을 재실행하지 않는다.
- 같은 세션의 새 완료 알림 교체 여부, 대기 중인 알림 프로세스 정리 정책은 구현 시 정한다.

### dunst의 클릭 버튼

- 왼쪽 클릭으로 액션을 실행하기로 정리했다. 오른쪽 클릭 언급은 사용자가 오타로 정정했다.
- 도구·설정·역할 분담 안내는 `bash scripts/dunst-action-help.sh`로 출력한다.
  이 스크립트는 설정을 자동 수정하거나 알림을 보내지 않는다.
- 별도 적용 스크립트 `python3 scripts/configure-dunst-action.py`는 기본 미리보기다.
  `--apply`는 기존 사용자 설정(없으면 시스템 설정)을 백업하고 왼쪽 클릭 옵션만
  바꾼 사용자 설정을 저장한 뒤 dunst를 재로드한다. 이번 실행은 사용자가 예외적으로
  허용했다. 이 허용은 앞으로 설정을 자동 변경할 상시 권한이 아니다.
- 해당 1회 허용으로 사용자 dunstrc 생성·원본 백업·왼쪽 클릭 옵션 적용·dunst
  재로드까지 완료했다. 앱의 액션 연결은 아직 미구현이다.
- 설치된 notify-send 0.8.8은 action 이름을 stdout으로 반환하는 옵션을 지원한다.
- dunst 기본 설정은 왼쪽 클릭이 닫기, 가운데 클릭이 action 실행이다.
- 따라서 설정 변경 없이 가운데 클릭으로 이동을 지원할 수 있다.
- 왼쪽 클릭으로 이동하려면 dunst의 `[global]`에
  `mouse_left_click = do_action, close_current`가 필요하다.
- 이는 다른 앱의 알림 클릭에도 영향을 줄 수 있다. 실제 변경 범위와 방법은
  추가 논의하며, 현재 문서 작성은 설정 변경의 승인이 아니다.
- 알림 전송 인자만으로 dunst의 왼쪽 클릭 매핑을 강제하지 않는다.

참고: [dunst FAQ](https://dunst-project.org/documentation/faq/),
[알림 액션 명세](https://specifications.freedesktop.org/notification/1.3/basic-design.html).

## 구현 순서와 검수

1. 누락된 재개 세션의 발견·제목·창 연결을 조사하고 3개 세션 재현 사례를 회귀 검증한다.
2. 쌍 → 실제 워크스페이스 → 모든 에이전트 구조와 현재 포커스 표시를 구현한다.
3. 행별 Enter·클릭·n 이동과 창 이동 추적을 검증한다.
4. 짧은 알림 문구와 세션별 완료 알림을 검증한다.
5. 비동기 action 수신·클릭 시점의 쌍/창 이동·대기 프로세스 정리를 구현한다.

쌍 항목 사용자 지정 이름 기능과 일반 승인 대기 감지는 후속 논의로 유지한다.
