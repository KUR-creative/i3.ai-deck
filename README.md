# i3.ai-deck

i3 전체의 Codex 세션을 나열하고 해당 창으로 이동하는 작은 TUI.
창 배치와 에이전트 실행은 기존 i3와 터미널이 담당한다.

현재 단계: 중간 사용이 가능한 첫 버전. 설치 없이 소스에서 실행한다.

다중 에이전트 목록·`[0]` 표시를 구현했으며, 짧은 알림·알림 액션의 미구현 계획과
재개 세션 누락 사례는 [다음 변경 계획](docs/PLAN.md)에 정리했다.

dunst의 왼쪽 클릭 액션 설정과 역할 분담은
`bash scripts/dunst-action-help.sh`로 확인할 수 있다. 안내만 출력하며 설정은 수정하지 않는다.

## 실행

일반 터미널에서 실행한다. 이 앱을 위한 sudo나 i3 설정 변경은 필요 없다.

```bash
cd ~/dev/i3.ai-deck
python3 ai_deck.py
```

다른 터미널에서도 같은 명령으로 열 수 있다. 첫 실행 시 서버를 자동 시작하며
TUI에서 `q`를 눌러도 서버와 Codex는 유지된다.

| 조작 | 동작 |
| --- | --- |
| j/k, 위/아래 | 행 선택 |
| g / G | 목록 처음 / 끝 선택 (이동은 Enter) |
| Enter, 마우스 단일 클릭 | 쌍 전환 후 선택한 에이전트 창 또는 빈 워크스페이스 포커스 |
| n | 다음 질문·미확인 완료 에이전트로 즉시 이동 (같은 쌍 내부도 포함) |
| 마우스 휠 | 목록 위/아래 |
| q, Esc | 현재 TUI만 닫기 |

```bash
python3 ai_deck.py --list         # 같은 서버의 현재 상태를 JSON으로 확인
python3 ai_deck.py --stop-server  # 서버 종료; 다음 실행 시 세션 재발견
```

코드를 업데이트한 뒤에는 서버도 위 명령으로 종료하고 TUI를 다시 연다.
기본 소켓·로그는 `$XDG_RUNTIME_DIR/i3-ai-deck/`에 두며, 환경 변수가 없으면
`~/.cache/i3-ai-deck/`를 쓴다. `--socket PATH`로 테스트 서버를 분리할 수 있다.

## 완료 알림

서버가 새 완료를 감지하면 다음처럼 쌍 번호와 대화 제목을 알린다.

```text
3번 쌍 완료
i3 알림 설정하기
```

- `notify-send -a Codex -u normal -t 0`과 녹색 배경 `#86EFAC`, 글자색 `#052E16`,
  큰 글씨를 사용한다. `notify-send`는 시스템에 설치되어 있어야 한다.
- 제목은 최대 40칸 표시폭(한글 약 20자)으로 줄이고 긴 경우 끝에 `…`를 붙인다.
  제목의 줄바꿈은 정리하고 마크업 문자는 이스케이프한다.
- 서버가 보내므로 TUI를 여러 개 열어도 같은 완료는 한 번만 알린다.
  TUI가 모두 닫혀 있어도 서버가 실행 중이면 알린다.
- 처음 발견한 세션의 기존 완료는 다시 알리지 않는다. 이후 새 완료부터 알린다.
  현재 보고 있는 에이전트의 새 완료도 알린다.
- 위치를 연결할 수 없으면 번호를 추측하지 않고 `위치 미확인 완료`로 알린다.
- 알림 실패는 서버 로그에 남기며 목록·창 이동 기능은 계속 동작한다.

## 확정 요구사항

- Python 표준 라이브러리만 사용한다. TUI는 curses, 통신은 Unix 소켓.
- 기존 `codex` 실행 명령을 그대로 쓴다. 실행 래퍼를 요구하지 않는다.
- 시작 전에 이미 실행 중인 로컬 Codex 세션도 자동 발견한다.
- 항목 이름은 Codex 대화 제목이다. Codex의 rename 변경을 따라 갱신한다.
  예: `i3 알림 창으로 이동 설정`. TUI 자체의 별도 이름 편집은 만들지 않는다.
- 활성 목록은 `[0]`, `[1]`, …, `[9]` 순서이며 각 쌍의 왼쪽·오른쪽 워크스페이스
  아래 모든 에이전트를 독립된 행으로 표시한다. F10은 표시만 F0로 바꾼다.
  대표 제목 전환과 `(+N)` 표시는 제거했다. 상단 제목 행도 없다.
- 현재 쌍과 워크스페이스 이름에 청록색 배경을 칠하고 실제 포커스된 에이전트에
  `>`를 표시한다. TUI에 포커스하면 에이전트의 `>`는 사라진다. 완료는 상태 글자만
  녹색, 키보드 선택 행은 중립색 반전이다. 포커스 상태는 모든 TUI에서 공유한다.
- 상태를 색상과 기호/문자로 표시한다. 목표 상태는 작업 중, 입력 대기,
  완료, 유휴, 종료, 확인 불가이다. 감지할 수 없는 상태를 추측해 표시하지 않는다.
- `j`/`k`와 위/아래 화살표로 선택하고 Enter로 이동한다. `g`/`G`는 처음/끝을 선택한다.
- 마우스 단일 클릭으로 해당 항목에 바로 이동하고, 휠로 목록을 스크롤한다.
- `n`은 현재 선택 다음부터 순환하며 다음 확인 대상(질문/입력 대기,
  미확인 완료 등)을 찾아 즉시 이동한다. 대상이 없으면 아무 동작도 하지 않는다.
  작업 중·확인한 완료·종료 항목은 건너뛴다.
  서버에서 최신 상태를 읽고 대상을 결정하며 같은 쌍 안의 다른 에이전트도 포함한다.
  다음 대상이 없으면 이동하지 않고 안내를 표시한다.
- 워크스페이스는 물리 워크스페이스 하나가 아닌 듀얼 모니터 쌍이다.
  활성 세션은 현재 쌍(F0/0, F1/1, …, F9/9), 왼쪽·오른쪽 순으로 정렬한다.
  같은 워크스페이스에서는 최초 발견 순서를 유지한다. 정렬이 바뀌어도
  선택한 세션 ID는 유지한다. 종료된 세션은 삭제하지 않고
  목록 뒤로 보낸다. 종료 항목 내부 순서는 최초 발견 순서를 유지한다.
- 에이전트 없는 워크스페이스는 회색 빈 행으로 표시하며 Enter·클릭으로 이동한다.
  10개 쌍의 양쪽 워크스페이스를 표시하며 아직 생성하지 않은 곳도 포함한다.
- i3 창 이동 시 목록 위치를 갱신하고, 이동 요청 시점에도 현재 위치를 재확인한다.
- 완료의 미확인 표시는 그 에이전트 창에 실제 포커스가 갈 때 지운다.
  워크스페이스가 보이거나 TUI를 열었다는 이유만으로 지우지 않는다.
- 서버를 재시작하면 실행 중인 세션만 재발견한다. 종료 기록·미확인 여부를
  영구 저장하지 않는다. 종료 항목은 해당 서버가 살아 있는 동안만 남는다.
- 여러 터미널에서 TUI를 동시에 열 수 있다. 모든 클라이언트는 같은
  세션·이름·상태·미확인 여부를 본다. 선택 커서는 클라이언트마다 독립적이다.
- 데스크톱 알림은 새 작업 완료를 지원한다. 터미널 분할과 tmux 연동은 제외한다.
- 이동과 확인 처리는 i3 창 단위다. Ptyxis 내부 탭 전환·선택 추적은 구현하지
  않는다. 여러 Codex 세션이 같은 i3 창을 쓰면 이동 대상과 확인 범위도 같다.
  Herdr 연동은 범위에서 제외한다.
- 구현과 커밋은 작고 아토믹하게 나눈다. 설치·전역 설정 수정은 별도 작업이다.
- `~/.config/i3/`의 파일은 수정하지 않는다. 반드시 수정해야 한다면 사전에
  사용자에게 이유를 설명하고 명시적 허가를 받는다. 현재 설계에는 수정이 필요 없다.

## 듀얼 모니터 이동

근거: `~/.config/i3/config.d/workspaces.conf`.

| 슬롯 | 왼쪽 DP-1 | 오른쪽 HDMI-0 |
| --- | --- | --- |
| 1..9 | 11:F1 .. 19:F9 | 1:1 .. 9:9 |
| 10 (키패드 0) | 20:F10 | 10:0 |

현재 Mod+키패드는 왼쪽 워크스페이스, 오른쪽 워크스페이스 순서로 전환하며
오른쪽에서 끝난다. 앱은 같은 쌍을 전환한 뒤 **선택한 에이전트 창**에
포커스한다. 이는 사용자가 선택한 최종 동작이다.

키 입력 합성 대신 같은 i3 IPC 명령을 호출한다. 예를 들어 슬롯 3:

```text
workspace --no-auto-back-and-forth number "13:F3";
workspace --no-auto-back-and-forth number "3:3";
[con_id=<현재 대상 창 ID>] focus
```

창 이동 후에는 현재 i3 트리에서 워크스페이스를 다시 알아낸다.
등록 당시의 워크스페이스를 계속 사용하지 않는다. 없는 창에는 이동하지 않으며,
워크스페이스 쌍을 판별할 수 없을 때의 정책은 아래 미결정 항목으로 남긴다.

전체 이름을 보존하는 이유: 숫자 `12`만 전달하면 없는 워크스페이스가 `12:F2`가
아닌 `12`로 생성되어 i3의 모니터 할당 규칙을 적용받지 못한다. 이는 한쪽 모니터만
전환되던 버그의 원인이었다. 전환 뒤에는 실제 표시된 양쪽 번호를 재확인한다.

## 작은 구조

- 서버 하나가 Codex 상태 수집, i3 창 연결, 읽음 처리와 공유 상태를 소유한다.
- TUI는 서버 상태를 표시하고 이동 요청만 보낸다. 에이전트를 실행하지 않는다.
- Unix 소켓으로 짧은 JSON 메시지를 교환한다. 웹 서버와 외부 DB는 쓰지 않는다.
- 공유 상태는 서버 메모리에만 둔다. 재시작 시 실행 중인 세션을 다시 수집한다.

## 구현 전에 확인할 것

- 설치 환경: codex-cli 0.169.0, Python 3.14.4, Ptyxis, i3/X11.
- `~/.codex/session_index.jsonl`에 `id`, `thread_name`, `updated_at` 필드가 있다.
  제목과 rename 반영에 사용할 수 있는지 확인한다.
- Codex 프로세스 → 세션 ID → i3 창 연결을 검증한다. Ptyxis는 여러 창이
  프로세스를 공유할 수 있으므로 PID나 프로젝트 경로만으로 단정하지 않는다.
- 로그/이벤트에서 작업 시작·완료·입력 대기·종료를 구분할 근거를 검증한다.
  Codex app-server 같은 별도 실행 모드로 사용 방식을 바꾸지 않는다.
- 기존 Codex 설정에는 SessionStart 훅이 있다. 기존 훅을 덮어쓰지 않는다.
  로그 관찰로 부족한 경우에만 필요한 추가 연동을 구체적으로 제안한다.
- 로그 내용이나 프롬프트 본문을 별도 저장하지 않고 필요한 식별자·상태만 다룬다.

## 첫 버전의 구현과 제한

- `/proc`에서 현재 사용자의 Codex가 열고 있는 rollout 파일을 찾는다.
  명시적인 사용자 스레드를 수집하고 내부 guardian 등은 제외한다. 재개한 세션의
  출처가 `vscode`여도 수집하며 한 백엔드의 여러 사용자 세션을 모두 수집한다.
  구형 로그는 cli/vscode 출처를 지원한다. 파일을 열지 않은 세션은 수집되지 않는다.
  래퍼·Codex 훅 변경은 없다.
- 제목은 `session_index.jsonl`, 상태는 rollout의 `task_started`, `task_complete`,
  `turn_aborted` 등에서 읽는다. 명시적인 `request_user_input` 도구 요청도 감지한다.
  일반 승인 대기·모든 형태의 질문을 감지하는 것은 아직 지원하지 않는다.
- Ptyxis가 여러 창에 같은 PID를 사용하므로 프로젝트 이름이나 PID만으로 창을
  추측하지 않는다. 고유한 Codex 대화 제목과 창 제목의 일치로 연결하고,
  이후에는 같은 i3 창 ID를 추적한다. 중복 제목·숨겨진 내부 탭·커스텀 터미널
  제목 등으로 연결할 수 없으면 `위치 불명`으로 표시하고 에이전트로 이동하지 않는다.
  중복 제목 중 로그가 작업 중이고 한 창에만 Codex의 진행 스피너가 있으면 그 창을
  연결한다. 이는 제목 기반 연결의 보조 근거이며 범용 터미널 식별 API는 아니다.
  끝내 구분할 수 없으면 후보 쌍에 `연결 불명`을 표시한다. 연결 실패를 `빈 쌍`으로
  단정하지 않으며 이 행에서는 쌍 전환만 한다. 제목을 바꾸고 터미널 창 제목도
  갱신되면 다시 연결한다.
- i3 창/워크스페이스 이벤트와 1초 주기 갱신으로 쌍·상태를 공유한다.
  이동 직전에도 위치를 다시 읽는다. 터미널 내부 탭 전환은 하지 않는다.
- 포커스 이벤트로 짧은 방문도 완료 확인에 반영한다. 에이전트 제목은 포커스에
  따라 교체하지 않고 각 행에 유지한다. 실제 현재 포커스는 i3 트리에서 확인한다.
- 마우스는 누를 때 선택하고 놓을 때 이동한다. 첫 누름을 터미널이 포커스 획득에
  사용해 놓음만 전달한 경우도 처리하며, 누름/놓음 한 쌍으로 두 번 이동하지 않는다.
- 이미 완료된 상태로 재발견한 세션은 미확인으로 시작한다. 현재 포커스된
  에이전트는 확인 처리한다. 재시작 전 읽음/종료 기록을 디스크에 보존하지 않는다.
- 빈 행으로 이동하면 두 워크스페이스를 열고 선택한 쪽 워크스페이스에서 끝난다.
  에이전트 행은 선택한 에이전트의 실제 창에서 끝난다.

## 후속 기능

- 쌍 항목에 사용자 지정 이름을 붙이고 수정하기. 기본값은 대표 에이전트 제목이며,
  이 이름은 Codex 대화 rename과는 별개다. 키와 보존 정책은 구현 시 결정한다.
- Codex의 일반 승인 대기를 정확히 감지할 수 있는 추가 이벤트 조사.

## 검증

```bash
python3 -m unittest discover -s tests -v
```

Unix 소켓을 막는 샌드박스에서는 소켓 통합 테스트에 일반 호스트 실행이 필요하다.
실환경에서 제목·상태·F3/3 연결을 읽기 전용으로 확인했고, 임시 서버의 두 클라이언트
동시 실행·상태 공유·종료를 검증했다. 실제 PTY에서 한글 렌더링, j/k/q, Enter,
n, 마우스 입력을 검증했다. 마우스 놓음 단독·누름/놓음·클릭 이벤트도 회귀 테스트한다.
실제 i3 IPC로 10개 쌍 전체를 전환하여 왼쪽 DP-1, 오른쪽 HDMI-0 배치를 확인했다.
같은 쌍의 `i3 알림 설정하기`를 짧게 포커스한 뒤 TUI로 돌아와 대표 제목이 반영되는
것도 실제 임시 서버로 확인했다. 검증 후 원래 양쪽 워크스페이스와 창 포커스를 복원했다.

## 기본 동작과 검증 과제

- 질문/입력 대기는 창을 봤다는 이유로 상태 자체를 완료로 바꾸지 않는다.
  실제 Codex 이벤트에서 대기 해소가 확인될 때까지 확인 대상에 남긴다.
- 기본 종료 키는 `q`이며 해당 TUI만 닫는다. 다른 클라이언트와 에이전트는
  계속 실행된다. 서버는 첫 클라이언트가 필요할 때 자동 시작하는 구조를 제안한다.
- 워크스페이스 쌍 밖의 대상은 임의의 쌍을 선택하지 않고 대상 창만 포커스한다.
- 세션을 창에 확실히 연결할 수 없으면 위치 확인 불가로 표시하고 이동하지 않는다.
- Ptyxis의 내부 탭이 각각 PTY를 갖는 것과 i3가 창만 관리하는 것은 별개다.
  세션은 개별 항목으로 수집하되 이동은 사용자가 요청한 i3 창까지만 처리한다.
- 상태 수집 및 기존 세션 자동 연결의 정확성은 다음 단계에서 검증한다.

## 작업 순서

1. 요구사항 문서와 미결정 사항 정리.
2. Codex 세션/상태/창 연결 가능성을 읽기 전용으로 검증하고 근거 문서화.
3. 공유 상태 서버와 통신. 중복 서버와 동시 클라이언트 검증.
4. 최소 목록 TUI와 키보드·마우스 조작.
5. 워크스페이스 쌍 전환, 실제 대상 창 포커스, 미확인 처리.
6. 실행 방법과 제한 문서화. 실환경 조작은 사용자 흐름을 방해하지 않게 검증.
